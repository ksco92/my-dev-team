## Frontend defaults (project conventions override)

- **Components.** Single responsibility; composition over inheritance; props/bindings are the
  public API — minimize and document them; split past ~150 lines; co-locate styles, tests, types.
- **State.** Local by default, lifted only when truly shared; derive rather than store; single
  ownership; server state (fetch/cache/refetch) separate from client UI state.
- **Accessibility (non-negotiable).** Accessible names on every interactive element; descriptions
  on images/icons or marked decorative; flexible text sizes; 44×44 pt / 48×48 dp tap targets;
  tested with a screen reader; reduced-motion respected; WCAG AA contrast; focus trapped in modals
  and returned on dismiss; keyboard navigable end to end on web.
- **Responsive.** Mobile-first; adaptive layouts via size classes / breakpoints / flex / grid;
  content dictates breakpoints; test the smallest and largest supported sizes; handle orientation
  and multitasking.
- **Visual.** Platform conventions (HIG, Material, native web); semantic/system colors for
  automatic dark/light; design tokens, never hardcoded colors; a 4/8 pt spacing scale; 60 fps.
- **Performance.** Lazy-load off-screen views; minimize render/body work; no retain cycles in
  closures; right-sized images; profile with platform tools before optimizing.

Testing deltas: 95%+ coverage applies to logic (view models, formatters, validators, state
transitions), best-effort on rendering; component tests cover empty/loading/error/populated states
and accessibility names; UI tests cover the critical paths; don't test framework behavior or
generated code. Decision deltas: platform conventions over custom UI; composition over
configuration; the more accessible option when trading off; three similar views over a premature
generic one; accessibility from the first commit.

## Learned patterns

Cross-project only; repo-specific lessons (a capture flow's mechanics, a framework quirk) go to
that repo's `.claude/rules/` or your project memory. You do not edit this file — propose a bullet.

- When a migration deletes a toolchain, audit what it configured implicitly (a Jest `resetMocks`
  default inside `react-scripts`, a `browserslist`-driven transpile floor), not just its tracked
  files — diff the old tool's own defaults against the new config before claiming parity.
- Never `pkill` by name pattern against a shared GUI-managed system service (Postgres.app,
  Docker Desktop helpers) to unstick a hung connection; kill only the port-bound process you
  started (`lsof -ti:<port>`), and if the shared service looks wedged, stop and report.
